# Test Strategy — Car Rental System

## Критичні сценарії
1. Оренда недоступного авто — повинна кидати виняток
2. Повернення/скасування неактивної оренди — повинна кидати виняток
3. Збереження і відновлення стану з JSON — дані не повинні губитись
4. Розрахунок вартості з різними стратегіями — повинен бути точним
5. Завантаження пошкодженого JSON — програма не повинна крашитись

## Що найважче тестувати
- JsonRepository — потребує реальної файлової системи → інтеграційні тести з temp файлами
- Program.cs / AppRunner — залежить від Console.ReadLine() → не тестуємо напряму
- RentalService з реальними репозиторіями → інтеграційні тести

## Де потрібні mocks, де реальна інтеграція
- Юніт-тести: InMemory репозиторії як замінники (вже є)
- Інтеграційні тести: реальні JsonRepository з тимчасовими файлами

## Негативні сценарії що можуть зламати проєкт
1. Пошкоджений cars.json — перевірено (graceful fallback)
2. Спроба орендувати вже зайняте авто
3. Подвійне завершення оренди
4. Порожня колекція при поверненні
5. Некоректні дати (кінець раніше початку)
